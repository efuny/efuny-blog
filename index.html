维护案例

一次迁移里拆出来的 3 个可复用经验

这次维护的核心不是跑命令，而是把可回滚、可验证和不误伤数据盘放在第一位。

Case 01 系统盘迁移

SD 卡引导，SSD 运行系统

HP Gen8 的 SATA5 光驱位无法稳定独立启动，因此保留 SD 卡作为 BIOS/GRUB 入口，把 Linux 根分区切到 Intel SSD。

  • 先初始化 SSD、复制系统，再给 SSD 安装 GRUB 做独立启动测试。
  • 独立启动失败后，只修改 SD 卡 GRUB 的 kernel root UUID，保留 search UUID 指向 SD 卡 /boot。
  • 最终验证 / 挂载到 Intel SSD，SD 卡旧系统分区卸载，仅保留引导职责。
Case 02 风险盘迁移

先抢数据，再讨论修盘

数据盘 1 对应 WD-WCAV5M641288，SMART 里出现 1 个重映射扇区和 1 个待映射扇区，但 Btrfs 还没有记录读写错误。

  • 确认 /vol1 是风险盘，/vol2 基本空闲且容量足够承接数据。
  • 优先复制 /vol1/1000 用户数据，再备份 @appdata、@appmeta、@appcenter 和 @sysappmeta。
  • 不贸然执行 btrfs check --repair，等关键数据安全后再安排 SMART 长测。
Case 03 Docker 落盘优化

让飞牛看到 /vol2，实际写入 SSD

飞牛应用中心只允许选择存储空间 1/2/3，无法直接选择系统 SSD，所以用 /vol2/docker 做表面路径，绑定到 SSD 的 /opt/docker。

  • 冷迁移 /vol1/docker 到 /opt/docker，保留旧目录作为可回滚备份。
  • 让 daemon.json 继续使用 /vol2/docker，避免被飞牛界面重写成其他存储空间。
  • 用 systemd mount unit 持久化 bind mount，重启后验证容器和挂载都恢复。
